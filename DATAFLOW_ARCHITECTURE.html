DataFlow Manager

Django 資料庫管理工具 — 架構與技術文件（Python 視角）

1. 項目概覽

DataFlow Manager 是一個以 Django 5.2 為基礎的資料庫管理工具，直接操作 PostgreSQL 資料表，無需額外抽象層。提供兩種介面：

  • Web UI — DB Explorer（瀏覽表格、匯入 CSV、匯出、刪除）
  • CLI Wizard — 互動式終端向導（python manage.py dataflow）

核心設計原則：pandas 讀取 → 直接 SQL 插入，不經過任何中間快取層。

4. Web UI — 核心 Python 邏輯

4.1 資料表探索 db_explorer()

呼叫 db_explorer.get_all_tables()，底層使用 Django 的 connection.introspection API：

from django.db import connection

tables = connection.introspection.table_names()         # 所有表格名稱
cols   = connection.introspection.get_table_description(cursor, table_name)  # 欄位描述

每個表格附有：名稱、行數、欄數、分類（django-app / system / dataflow）。

4.2 CSV / JSON 匯入 _import_uploaded_csv_to_table()

上傳的檔案流程：

# 1. 讀取（pandas）
df = pd.read_csv(tmp_path)           # 或 read_excel / read_json

# 2. 匹配欄位（只插入 CSV 與 DB 表格共同有的欄位）
insert_cols = [c for c in df.columns if c in db_columns]

# 3. 批量插入
sql = f"INSERT INTO {table} ({cols}) VALUES ({placeholders})"
cursor.executemany(sql, values)

# 4. 重置 PostgreSQL serial sequence
_reset_table_sequence(table_name, pk_column)

若目標表格不存在，_create_table_from_csv() 會先用 _sql_type_for_series() 推斷每欄的 SQL 類型（BIGINT / TIMESTAMPTZ / TEXT…）再建立表格。

4.3 SQL 類型自動推斷 _sql_type_for_series()

def _sql_type_for_series(series):
    if pd.api.types.is_integer_dtype(series):    return 'BIGINT'
    if pd.api.types.is_float_dtype(series):      return 'DOUBLE PRECISION'
    if pd.api.types.is_datetime64_any_dtype(series): return 'TIMESTAMPTZ'
    # 偵測 ISO 日期字串（如 2026-06-04T16:00:00+00:00）
    if series.dtype == object and sample.str.match(r'^\d{4}-\d{2}-\d{2}[T ]').all():
        return 'TIMESTAMPTZ'
    return 'TEXT'

這避免了 datetime 欄位被錯誤地建立為 TEXT，防止後續 timestamp >= text 類型錯誤。

4.4 匯出 db_explorer_export()

# 直接查詢 → pandas DataFrame → 輸出
cursor.execute(f"SELECT {cols} FROM {table}")
df = pd.DataFrame(data)

df.to_csv(...)    # CSV
df.to_excel(...)  # Excel（需先 _prepare_dataframe_for_excel() 去除 timezone）
df.to_json(...)   # JSON（force_ascii=False, date_format='iso'）

批量匯出（多表格選擇）會把每個表格打包進一個 ZIP 檔案回傳給瀏覽器。

5. CLI Wizard — 互動式向導

5.1 啟動方式

python manage.py dataflow   # 啟動互動向導（無需任何參數）

管理命令 management/commands/dataflow.py 只有一行邏輯：呼叫 cli.run_wizard()。向導結束後可選擇返回主目錄或退出，以遞迴呼叫實現。

5.2 終端輔助函數

向導的所有終端輸出由四個簡單函數驅動，使用 ANSI escape code 顯示顏色：

_step(n, label)          # 藍色步驟標題：  Step 2  What to do?
_ok(msg)                 # 綠色成功：  ✔  17 rows imported
_err(msg)                # 紅色錯誤：  ✘  File not found
_ask(prompt, default)    # 文字輸入：  › Name [course]: _
_choose(prompt, options) # 數字菜單，返回選中的 value（非 label）

_choose() 接收 [(label, value), ...]，用戶輸入數字，返回對應 value（可以是任意 Python 物件，如 True/False 或字串 sentinel）。

5.3 Step 1 — 顯示資料表

向導啟動後立即查詢所有資料表，按前綴分為兩組：

_SYS = {'django_', 'auth_', 'dataflow_', 'taggit_'}

app_tables = sorted(t for t in all_table_names
                    if not any(t.startswith(p) for p in _SYS))
sys_tables = sorted(t for t in all_table_names
                    if any(t.startswith(p) for p in _SYS))

每個表格即時執行 SELECT COUNT(*) 顯示行數。後續所有操作（查看 / 匯出 / 匯入 / 清除）只向用戶展示 app_tables。

5.4 Step 2 — 動作菜單

選項動作代碼說明
View table data'view'逐筆顯示記錄，超過10筆自動分頁
Export data to file'export'選擇單一表格或全部，輸出 CSV/Excel/JSON
Import file into table'run'支援單一檔案或整個資料夾
Clear table data'delete'DELETE 表格所有行（保留結構），支援全部清除
Quit'quit'立即退出

5.5 查看資料（View）

每筆記錄以垂直 key: value 格式顯示，超過80字元的值自動截斷。分頁邏輯：

PAGE = 10
if total <= PAGE:
    _print_records(all_rows, 0)         # 直接全部顯示
else:
    while True:
        page_rows = all_rows[start:start + PAGE]
        _print_records(page_rows, start)
        choice = _choose('Navigation:', nav)  # Next / Previous / Back
        if choice == 'back': break
        page += 1 if choice == 'next' else -1

5.6 匯出（Export）

查詢資料 → 建立 pandas DataFrame → 寫出檔案：

with _conn.cursor() as cur:
    cur.execute(f"SELECT * FROM {table}")
    cols = [d[0] for d in cur.description]
    rows = cur.fetchall()

df = pd.DataFrame(rows, columns=cols)

df.to_csv(path, index=False)
df.to_excel(path, index=False)
df.to_json(path, orient='records', indent=2,
           force_ascii=False,    # 保留中文字符
           date_format='iso')   # 日期輸出 ISO 格式而非毫秒時間戳

選擇「All application tables」時，依次對每個 app_tables 中的表格執行上述流程，各自輸出獨立檔案。

5.7 匯入（Import）

支援兩種模式：

模式判斷條件行為
單一檔案os.path.isfile(path)用戶選擇目標表格，可指定 replace 或 append
整個資料夾os.path.isdir(path)掃描所有 .csv/.xlsx/.json，以檔名作為表格名稱批量匯入

核心匯入邏輯在 _import_file_to_table(conn, file_path, table_name, replace)：

# 1. 讀取檔案
df = pd.read_csv(file_path)  # / read_excel / read_json
df = df.replace({pd.NA: None, float('nan'): None})  # 統一 null 值

# 2. 若表格不存在 → 推斷類型並建立
col_defs = [f'{quote(col)} {_sql_type_for_series(df[col])}'
            for col in df.columns]
cursor.execute(f"CREATE TABLE {table} ({', '.join(col_defs)})")

# 3. 只插入 DB 中已存在的欄位（自動跳過多餘欄位）
db_cols = {c.name for c in conn.introspection.get_table_description(...)}
insert_cols = [c for c in df.columns if c in db_cols]

# 4. 批量插入（帶事務）
with transaction.atomic():
    if replace:
        cursor.execute(f"DELETE FROM {table}")
    cursor.executemany(sql, values)

5.8 清除資料（Clear）

選擇「All application tables」時，輸入 "ALL" 確認；選擇單一表格時輸入表格名稱確認，防止誤操作。

with _conn.cursor() as cur:
    for name in names:   # names = [table] 或 app_tables
        cur.execute(f"DELETE FROM {quote(name)}")
        _ok(f'All rows deleted from "{name}".')

使用 DELETE 而非 TRUNCATE，以確保外鍵約束不被違反（Django 的級聯刪除順序）。

6. 如何讀取 SQL 資料 — 連接原理

6.1 連接從哪裡來？

Django 在 settings.py 定義連接參數，啟動時建立一個全域 connection 物件，整個項目共用同一條連接：

# settings.py（宿主項目配置）
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': 'your_db',
        'HOST': 'localhost',
    }
}

# 任何 Python 檔案只需一行即可使用
from django.db import connection

DataFlow Manager 作為 Django App 安裝到宿主項目後，自動繼承宿主的 DATABASES 設定，因此能直接讀寫宿主項目的所有表格，無需額外配置。

6.2 如何讀取任意表格？

使用 DB-API 2.0 標準 cursor，無需預先定義 Django Model：

with connection.cursor() as cursor:
    cursor.execute("SELECT * FROM course")
    rows = cursor.fetchall()                      # → [(4, 'oo_456', 'INAINA', ...), ...]
    cols = [d[0] for d in cursor.description]    # → ['id', 'code', 'name', ...]

關鍵：cursor.description 是 DB-API 2.0 標準屬性，每個元素包含欄位名稱、類型代碼等。這讓系統能動態處理任何表格，不需要 Model 定義。

6.3 如何發現有哪些表格？

Django 的 DB Introspection API 直接查詢 PostgreSQL 的 information_schema：

# 列出所有表格
connection.introspection.table_names()
# → ['course', 'news', 'student', 'auth_user', 'django_migrations', ...]

# 取得欄位結構（名稱、PostgreSQL 類型代碼、是否允許 null）
connection.introspection.get_table_description(cursor, 'course')
# → [FieldInfo(name='id', type_code=23, null_ok=False), ...]

# type_code 是 PostgreSQL OID，例如：
# 23=INTEGER, 25=TEXT, 1114=TIMESTAMP, 1184=TIMESTAMPTZ, 701=FLOAT

這就是 DB Explorer 無需任何 Model 就能列出並分類所有表格的原因。

6.4 各元件如何共用同一連接

connection 是全域單例，所有元件都 from django.db import connection，指向同一個資料庫：

connection（全域物件，指向宿主 PostgreSQL）
    │
    ├─ db_explorer.py
    │   get_all_tables()  ──► introspection.table_names()
    │   get_table_schema() ──► introspection.get_table_description()
    │
    ├─ views.py（Web UI）
    │   db_explorer()      ──► get_all_tables() → 渲染 HTML 表格列表
    │   upload()           ──► pandas 讀取 → cursor.executemany() 插入
    │   db_explorer_export() ──► cursor.execute() → pandas → 檔案下載
    │
    └─ cli.py（CLI Wizard）
        run_wizard()       ──► introspection.table_names() → 終端顯示
        _import_file_to_table() ──► pandas 讀取 → cursor.executemany()

Web UI 和 CLI Wizard 操作的是同一個資料庫，區別只在於輸出方式：HTTP Response vs print()。

6.5 Web UI 如何把 SQL 資料傳給 Template？

# views.py
def db_explorer_table(request, table_name):
    with connection.cursor() as cursor:
        cursor.execute(f"SELECT * FROM {table_name}")
        cols = [d[0] for d in cursor.description]
        rows = cursor.fetchall()

    row_data = [{cols[i]: row[i] for i in range(len(cols))} for row in rows]

    return render(request, 'db_explorer_table.html', {
        'row_data': row_data,   # Python list of dicts → Template 直接遍歷
        'col_names': cols,
    })

<!-- db_explorer_table.html -->

    <td>{{ row|get:col }}</td>
  {% endfor %}
{% endfor %}

7. 關鍵 Django API 用法

7.1 DB Introspection（表格結構查詢）

from django.db import connection

# 取得所有表格名稱
connection.introspection.table_names()

# 取得欄位描述（名稱、類型代碼、null 允許等）
connection.introspection.get_table_description(cursor, table_name)

# 取得主鍵欄位名
connection.introspection.get_primary_key_column(cursor, table_name)

# 取得約束（外鍵等）
connection.introspection.get_constraints(cursor, table_name)

# 安全引用表格/欄位名（防止 SQL 注入）
connection.ops.quote_name(table_name)

7.2 Raw SQL 執行

from django.db import connection, transaction

# 單一查詢
with connection.cursor() as cursor:
    cursor.execute(f"SELECT * FROM {table}")
    rows = cursor.fetchall()
    cols = [d[0] for d in cursor.description]

# 批量插入（帶事務）
with transaction.atomic():
    with connection.cursor() as cursor:
        cursor.executemany(sql, values)

# 動態 ALTER TABLE（修復 text → timestamptz）
cursor.execute("""
    ALTER TABLE course
    ALTER COLUMN registation_expiry_date
    TYPE timestamptz USING registation_expiry_date::timestamptz
""")
