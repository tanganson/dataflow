DataFlow Manager

把你的 CSV 檔案自動變成資料庫 + 網頁介面

1. DataFlow 在做什麼？

一句話：你丟一個 CSV 檔案進去，它自動幫你建立資料庫表格 + 網頁後台，可以搜尋、排序、匯出。

它解決了什麼問題？

  • 拿到 CSV → Excel 打開 → 手動檢查格式
  • 欄位型別要自己猜
  • 想放進資料庫 → 手動寫 CREATE TABLE
  • 想給同事看 → 匯出 Excel 寄 email
  • 更新資料 → 重複以上全部步驟
  • dataflow run data.csv → 一行指令
  • 自動推斷 13 種型別
  • 自動 CREATE TABLE + 寫入資料
  • 即時網頁介面，搜尋排序匯出
  • 換規則 → dataflow clean 重新清洗

步驟 1：讀取檔案 — 一行指令，五種格式

傳統做法：拿到 CSV → 用 Excel/Python 打開 → 檢查編碼 → 處理缺失值 → 確認欄位名稱 → 才能開始處理。換一種格式又要重寫讀取程式碼。

DataFlow 的做法：無論什麼格式，都是一行指令。背後使用 Pandas 統一處理 CSV、Excel、JSON、Parquet、Feather 五種格式，自動處理編碼、NaN、欄位名稱。

python manage.py dataflow run data.csv --name "我的資料"
# 也支援: .xlsx  .json  .parquet  .feather

把「讀檔案」從 30 分鐘的資料工程變成 1 秒鐘的指令。

步驟 2：猜欄位型別 — 不再需要逐個 Model 去定義

傳統做法：手動建立 Django Model，每個欄位都要自己判斷型別、自己寫程式碼。20 個欄位 = 20 行程式碼。

DataFlow 的做法：取樣前 200 行，按 boolean → email → url → date → int → float → string 優先級自動推斷。

原始值                  推斷型別
alice@mail.com      →  email      (regex 驗證)
https://example.com →  url        (URL 格式檢測)
2023/09/02          →  date       (多格式日期解析)
85.5                →  float      (數值檢測)
true                →  boolean    (布林值關鍵字)

20 欄位的 Model 定義，從手寫 20 行變成 0 行。

步驟 3：清洗資料 — 靠 Rule 全自動化

傳統做法：寫一堆 if/else 檢查每個值 — 是不是 email？有沒有多餘空白？日期格式對不對？數字有沒超出範圍？

DataFlow 的做法：推斷出的型別自動轉成 Rule。清洗引擎 GenericDataCleaner 根據 Rule 逐行執行 13 種內建清洗函式：

清洗前                清洗後              使用的 Rule
"  S001  "       →   "S001"             string (trim 空白)
" YES "          →   true               boolean (轉布林)
"invalid-email"  →   ⚠️ 標記為錯誤      email (regex 驗證)
"2023/09/02"     →   "2023-09-02"       date (標準化日期格式)
"105" (上限100)  →   100.0              float (clamp 到 max)

全自動流水線。你只需要提供 Rule（或讓它自己推斷），不需要寫任何檢查邏輯。

步驟 4：存入資料庫 — 完美還原，而不是單純寫入

傳統做法：CSV 匯入 SQLite → 所有欄位變 TEXT。數字變字串、日期變字串。型別資訊永遠遺失。

DataFlow 的做法：雙重儲存（Dual-Write）：

┌─ JSON 備份 (DataRecord) — 保留原始彈性，方便回溯
└─ 真實 SQL 表格 (dataflow_dataset_N) — 每個欄位正確型別：
   int → IntegerField (可 SUM/AVG)    date → DateField (可日期篩選)
   float → FloatField (可計算)        url → URLField (可 URL 查詢)
   boolean → BooleanField (可過濾)    email → CharField(255) (可搜尋)
Rule 寫錯了？用 dataflow clean 重新清洗 — 從 JSON 備份取出原始資料，套用新 Rule，重建 SQL 表格。

步驟 5：網頁查看 — 有 UI，一目了然

傳統做法：資料在資料庫裡，要看必須寫 SQL。DataFlow 自動生成完整網頁操作介面：

功能傳統方式DataFlow
查看資料寫 SQL 查詢✅ 點擊資料集 → 即時顯示
搜尋WHERE column LIKE '%x%'✅ 搜尋框直接輸入
排序ORDER BY column✅ 點擊欄位標題
匯出寫匯出程式✅ 下拉選單 → CSV/JSON/Excel
刪除DROP TABLE + DELETE✅ 一鍵刪除（含 SQL 表格）
重新清洗全部重做✅ 上傳新 Rule → 自動重建
型別標籤看程式碼才知✅ Schema 彩色標籤

從「寫 SQL」變成「點滑鼠」。非技術人員也能獨立操作。

5.1 動態建立 Django Model — type() 三參數

正常 Django Model 是寫死在程式碼中的。但 DataFlow 的 CSV 欄位每次都不一樣，無法事先寫死。Python 的 type() 可以在執行階段動態建立類別：

MyModel = type('DynamicTable', (models.Model,), {
    'name': models.CharField(max_length=200),
    'price': models.FloatField(),
    '__module__': 'dataflow.schema_manager',
})
# MyModel 現在就是真正的 Django Model！可查詢、可寫入

比喻：一般 Model 是「預售屋」— 格局在蓋之前就畫好了。動態 Model 是「3D 列印」— 給它欄位名稱和型別，現場印出一個資料表。

CSV 欄位: name, email, score ↓ type() 動態建立 class DynamicTable(models.Model): name = CharField() / email = CharField() / score = FloatField() ↓ SchemaEditor CREATE TABLE dataflow_dataset_N (name VARCHAR, email VARCHAR, score REAL)

5.2 自動產生 SQL — Django SchemaEditor

SchemaEditor 將 Model 定義翻譯成資料庫的 CREATE TABLE 指令。不同資料庫自動產生不同 SQL。

with connection.schema_editor() as editor:
    editor.create_model(MyModel)
# SQLite:   CREATE TABLE "dataflow_dataset_5" ("id" integer PRIMARY KEY AUTOINCREMENT, ...)
# PostgreSQL: CREATE TABLE "dataflow_dataset_5" ("id" serial PRIMARY KEY, ...)

5.3 動態註冊 Model — Django App Registry

Model 建立後必須註冊到 Django 內部，Admin 和 ORM 才能找到它：

apps.all_models.setdefault('dataflow', {})['dynamictable_5'] = MyModel
apps.clear_cache()  # 清除 Django 內部快取

5.4 型別映射表 — 清洗型別 → SQL 型別

連接「清洗規則」和「資料庫欄位」的翻譯器：

RULE_TYPE_TO_FIELD = {
    'int': lambda: IntegerField    'float': lambda: FloatField
    'string': lambda: CharField    'email': lambda: CharField(255)
    'url': lambda: URLField        'date': lambda: DateField
    'boolean': lambda: BooleanField  'decimal': lambda: DecimalField
}
CSV: score, type=float, min=0, max=100 → RULE_TYPE_TO_FIELD['float'](required=False, default=0.0) → FloatField(null=False, default=0.0) → SchemaEditor → CREATE TABLE ... (score REAL DEFAULT 0.0)

三層 SQL Injection 防護

第 1 層：table_name 必須存在於 introspection.table_names() 白名單 第 2 層：所有識別字透過 connection.ops.quote_name() 跳脫 第 3 層：所有數值使用 %s 參數化查詢，永不拼接字串

6. 如何在你的 Django 專案中使用？

  1. 安裝套件 
    pip install -e /path/to/dataflow_manager
  2. 編輯 settings.py 
    INSTALLED_APPS = [..., 'dataflow']
MIDDLEWARE = [..., 'dataflow.middleware.RefreshDynamicAdminsMiddleware']
  3. 編輯 urls.py 
    path('dataflow/', include('dataflow.urls'))
  4. 執行 
    python manage.py migrate
python manage.py dataflow run data.csv --name "我的資料"

7. 常見問題

Q: 為什麼不用手動建立 SQL 表格？

schema_manager.py 中的 SchemaEditor 會根據 CSV 欄位自動執行 CREATE TABLE。

Q: 資料存在哪裡？

存在你 Django 專案的資料庫中（預設 db.sqlite3）。和其他 App 的資料在同一個資料庫。

Q: 支援哪些資料庫？

SQLite、PostgreSQL、MySQL 都支援。SchemaEditor 自動處理 SQL 方言差異。

Q: 可以匯入多大的檔案？

已測試過 4800 行 CSV，約 3 秒完成。大檔案有 tqdm 進度條顯示。

Q: CSV 有中文可以嗎？

可以。全程 UTF-8，中文欄位名稱和內容都沒問題。
